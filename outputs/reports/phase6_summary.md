## 2. 这份数据的真实结构（读后面的结论前必须先看）

下面三条不是推断，是从 5,492 万行里数出来、并用两种独立实现交叉验证过的：

1. 去重用户 **424,170** 个，`user_id` 连续覆盖 1~424,170，没有跳号。
2. **这 424,170 个用户全部在 1111 当天出现过，而且每人都至少有一次购买事件**。1111 当天的用户集合与全量用户集合完全相等（集合相等，不是近似相等）。
3. **1112 当天只有 46 行、0 次购买**，日志实际上在 1111 就结束了。

由此得到两个必须写进报告的口径限制：

- 这份竞赛数据的抽样口径是「11.11 当天有购买行为的用户」，**不是全站随机用户**。所以：
  - 「购买用户占比 = 100%」是抽样口径的必然结果，**这个数字没有信息量**，不能当成转化率或渗透率来讲；
  - 加购去重用户只有 **31,044** 人（占全部用户的 7.32%），同样受抽样口径影响，不代表平台真实加购率。
- 因为日志到 1111 就结束，**无法用本日志构造「1111 之后是否再购买」的标签**。复购标签只能沿用比赛方给出的 `label`（其观测窗口不在我们拿到的数据里）。这一点直接决定 Phase 8 的建模方式：特征只能用 1111 及之前的行为，标签来自外部，不能自己重新定义一遍复购。


## 3. 行为结构

- 全周期共 **54,925,330** 条行为事件，覆盖 **424,170** 个用户。
- 点击事件 **48,550,713** 条，占 **88.39%**，行为日志以浏览为主，符合电商流量结构。
- 购买事件 **3,292,144** 条，涉及 **424,170** 个用户。
- 有购买行为的用户 **424,170** 人，其中有 **387,252** 人购买事件 ≥2 次（占购买用户 **91.30%**）。

> 口径提醒：日志里没有会话 ID 和订单号，所以**不能**直接算「单次会话的点击→购买转化率」。上文的「用户占比」是 186 天累计口径，只能说明触达面，不能当作转化率。


## 4. 时间趋势

- 行为量最高的一天是 **1111**，10,582,633 条；当天 UV **424,170**。
- 购买事件最高的一天是 **1111**，1,223,354 条。
- 有效窗口 **185 天**（0511–1111），日均行为条数 **296,893**，日均 UV **38,720**。
  > 1112 仅有 **46 条、0 次购买**，属于数据截断的尾巴，因此不计入日均。若把 186 天全算进来，日均会变成 295,297，低估约 0.54%。
- **0519 → 0520 存在结构性跳变**：单日行为条数从 18,430 涨到 225,198（12.22×）。跳变前 9 天日均只有 21,680 条，跳变后日均 309,210 条，相差一个量级。判断为**数据采集覆盖不完整**（早期只覆盖了部分用户），所以上述「日均」把两段混在一起算，会低估后半段的真实强度；做趋势或基线对比时，应剔除前 9 天或分段说明。

## 9. 本阶段的局限（必须写在报告里）

1. `time_stamp` 只有 mmdd，没有年份，**不做工作日/周末对比**。没有确凿日历年出处，就不编造星期几。
2. 没有会话 ID / 订单号 / 金额，**不能算真实转化率、客单价、GMV**，任何此类数字都是编的。
3. 日志时间范围 0511–1112，缺少 1112 之后的数据，双十一后续长尾无法评估。
4. 用户画像的年龄/性别存在缺失（age_range 缺 2,217、gender 缺 6,436），分布图包含「未知」类别，不做插补。
