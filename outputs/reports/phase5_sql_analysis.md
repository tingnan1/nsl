## 1. 本次覆盖的 SQL 能力

| 技术点 | 用在哪 |
|---|---|
| CTE（`WITH`） | 每日汇总、品类排名、商家排名、用户分层 |
| `LAG()` 窗口函数 | 日环比 |
| `AVG() OVER (ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` | 7 日移动平均 |
| `RANK()` / `DENSE_RANK()` | 商家排名（并列处理） |
| `ROW_NUMBER() OVER (PARTITION BY ...)` | 商家内部按日排名 |
| `SUM() OVER (ORDER BY ... ROWS UNBOUNDED PRECEDING)` | 品类帕累托累计占比 |
| 条件聚合 `CASE WHEN` + 聚合函数 | 双十一当天 vs 前 7 日均值一行输出 |
| `EXPLAIN` 分区裁剪 | 验证分区设计有效 |

## 3. 关键发现

### 3.1 0519 → 0520 结构性断层被 SQL 独立证实

`LAG` 算出的日环比：

| 日期 | 行为条数 | 日环比 |
|---|---|---|
| 0519 | 18,430 | -4.22% |
| **0520** | **225,198** | **+1121.91%** |

前一天还在 1.8 万，次日跳到 22.5 万，**12.22 倍**。判断为早期数据采集覆盖不完整，因此「全期日均」把两段混算会严重低估后半段强度。

### 3.2 双十一

| 指标 | 前 7 天日均（1104–1110） | 1111 当天 | 倍数 |
|---|---|---|---|
| 行为条数 | 1,179,264 | 10,582,633 | **8.97×** |
| 购买事件 | 13,749 | 1,223,354 | **88.98×** |
| 活跃用户 UV | 95,718 | 424,170 | 4.43× |

购买事件的放大倍数（88.98×）远高于行为总量（8.97×）——说明 1111 不只是「人变多了」，更是**单位行为的转化效率大幅提升**。但要注意：这份数据的用户本来就是 11.11 买家，所以 UV 当天等于全量用户（424,170），这个 4.43× 不代表真实拉新。

### 3.3 品类高度分散，不存在垄断

TOP10 品类累计仅占购买事件 **23.21%**，第一名 cat_1213 也只有 2.90%。

| 名次 | 品类ID | 购买事件 | 占比 | 累计占比 |
|---|---|---|---|---|
| 1 | 1213 | 95,353 | 2.90% | 2.90% |
| 2 | 267 | 91,184 | 2.77% | 5.67% |
| 3 | 662 | 89,665 | 2.72% | 8.39% |
| … | | | | |
| 10 | 1438 | 64,490 | 1.96% | **23.21%** |

### 3.4 商家复购率：样本量越大，平均复购率越高——但小样本会造出假极值

| 样本量分组 | 商家数 | 组内平均复购率 | 最低 | **最高** |
|---|---|---|---|---|
| 500 以上 | 111 | **7.11%** | 1.09% | 29.04% |
| 100–499 | 476 | 5.42% | 0.00% | 28.19% |
| 30–99 | 927 | 5.22% | 0.00% | 43.24% |
| **< 30（不参与排名）** | 479 | 5.57% | 0.00% | **52.94%** |

样本量 500 以上的大商家平均复购率最高（7.11%），符合「大商家运营更稳」的直觉。而样本量 <30 的组里出现了 **52.94%** 的极端复购率——这正是小样本噪声，**印证了「样本量 <30 的商家不参与排名」这条规则的必要性**：不做这个限制，排行榜第一名很可能是某个只有两三个样本的商家。

### 3.5 头部商家最旺的日子：1111 断层第一，其次 0626 和 0909

`ROW_NUMBER() PARTITION BY seller_id` 的结果，前三名商家（3828 / 3760 / 1）的购买峰值都高度一致：

| 商家 | 第 1 名日期 | 当日购买 | 第 2 名日期 | 第 3 名日期 |
|---|---|---|---|---|
| 3828 | 1111 | 10,105 | 0626 | 0909 |
| 3760 | 1111 | 6,519 | 0626 | 0909 |
| 1 | 1111 | 7,537 | 0517 | 0909 |

三个不同商家的次高峰都落在 **0626 和 0909**，说明这两天有平台级活动（不是单个商家的行为）。这是从数据里看出来的模式，具体是什么活动，数据集没有给出，不做猜测。

## 4. 分区裁剪验证

```sql
EXPLAIN SELECT COUNT(*) FROM fact_user_log
WHERE date_key BETWEEN 1101 AND 1111 AND action_type = 2;
```

```
partitions: p11          <- 只扫 1 个分区（共 8 个）
key: idx_month_action    <- 用上索引
type: range
Extra: Using where; Using index   <- 覆盖索引，不回表
```

对比修正前按 `RANGE(month)` 分区时 `partitions` 是全部 8 个分区，分区等于白建。改成 `RANGE(date_key)` 后才真正生效。
